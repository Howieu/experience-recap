# 深挖题目树（产品经理岗位，个人项目为主）

按顺序问；前一题定的结论是后一题的前提。每题先写“底层在问”给用户看，再给推荐答案。所有题目都要能从简历的某句话或上一题的回答自然引出；引不出来的题，面试官不会问，跳过。

## 1. 需求从哪来，根因是什么

- **底层在问**：你会不会像产品经理一样拆问题：谁、在什么场景下要完成什么事、现在怎么做、难在哪、为什么现有方案没满足。
- **讲法**：
  1. 产品是什么，核心用户是谁，在哪些场景用。开头不要把产品限定得太窄，面试官只看过简历。
  2. 怎么确定是真需求：三方印证。一手经历或行业案例（证明真有人这样做事）+ 外部调研（证明普遍，要有出处）+ 竞品实测（证明现有方案哪里不行）。竞品只作“现有方案为什么没满足”的证据，不讲成“别人做了、有缺陷、我们也做”。
  3. 分清症状、原因和门槛：用户常说的痛点（“取数要排队”）往往是症状；真正的原因是更底层的工作方式；“结果可信”这类是使用门槛，不是卖点。
  4. 方案：Agent 放在链路的哪几个环节、为什么放那里、怎么兜底（表格：环节 / 做什么 / 为什么放这里 / 怎么兜底）。
- **查证**：PRD、README、调研文档、竞品测试报告。调研数字逐条找出处。

## 2. 关键概念的产品立场

- **底层在问**：产品里最核心的那个概念（例如“异常”“预算”“相关”）你怎么定义，在两种用户利益之间怎么取舍（例如宁可少报还是宁可多报）。
- **讲法**：先说立场，再说具体怎么呈现给用户，再说考虑过的另一种做法和没用它的原因。追问常是“误报和漏报你更怕哪个”。
- **查证**：代码里的实际行为（打分规则、门槛、没给条件时怎么办），以代码为准。

## 3. 为什么用 AI / Agent，而不是规则、提示或现成工具

- **底层在问**：你知不知道什么该交给模型、什么不该；是不是为了 AI 而 AI；为什么不直接用现成的 Agent 平台或把知识写成提示 / skill。
- **讲法**：
  1. 先有不用模型的基线，它本身能用。
  2. 拿真实说法测基线，证明它在哪几处接不住。
  3. 模型只放在那几处；固定流程编排，不让模型自主决定步骤（如果是这样设计的）。
  4. 区分“写给模型读的”和“写给程序执行的”：流程知识（先看什么、报告怎么写）适合写成提示或 skill；错了也没人发现的硬口径（字段对应、指标定义、数字计算）要由程序强制执行。
  5. 对照实验最有说服力：同一批题，分别交给本产品、“同模型 + 提示自己做”、“强模型 + 提示自己做”，比准确性、稳定性和成本。
  6. 反向操作：有没有把模型的活收回给规则。这是“不堆 Agent”最有力的证据。
  7. 条件变了（模型更强、成本允许）会怎么演进。
- **查证**：触发条件、采用前的核对、降级逻辑、对照实验记录、提交记录里的增减。

## 4. 怎么评估它有没有用

- **底层在问**：你怎么证明效果，指标定义清不清楚，评测靠不靠谱。
- **讲法**：把评估拆成“结果能不能信”和“业务用不用”。指标分四层：
  1. 离线：回归用例、手算核对、预埋异常、对照实验；护栏指标（例如数字错误为 0、方向说反为 0）。
  2. 线上质量：点踩率；点踩连同当时的工具调用存下来，复核归因后加进回归测试。
  3. 采纳（北极星）：生成结果被用户认定“要处理 / 被采用”的数量和比例。不拿“生成了多少份”当北极星，生成几乎不花成本。
  4. 使用与价值：打开率、追问率、在业务会议里是否被使用。
  - 指标对上行业标准名和公式（CTR、CVR、加购率、GMV = 访客 × 转化率 × 客单价……），说清分母换成了什么。
  - 评测可信度排序：代码断言和回归用例 > 真人判断 > 模型评审（未校准前只看趋势）。
  - 没有用户时讲验证计划和**放弃条件**（要用户本人认同）。
- **追问**：“点赞率高能说明准吗？”“用户不点按钮，北极星不就失真了吗？”
- **查证**：评测脚本（能重跑就现场重跑），指标定义代码，反馈是否真的落库。

## 5. 最怕出的错怎么防

- **底层在问**：面试官的原话可能是“数据怎么保证准”，底层是“Agent 会不会编东西给用户”。先答这个。
- **讲法**：多层防线（模型没有这个权力 → 写了也会被拦 → 数字必须有出处），一个真实 bad case 的完整闭环，最后才讲数据源本身怎么保证准、哪些属于范围外。
- **查证**：模型能调用什么、校验规则、退回逻辑、回归测试。

## 6. 能力边界：哪些交给程序，哪些留给用户

- **底层在问**：产品会不会越界（编原因、给空泛建议、把相关说成因果），你怎么划这条线。
- **典型题**：“业务问‘为什么跌了’，你怎么回答？为什么不让模型直接分析原因？”“你会直接给业务建议吗？”“预测数怎么解释给业务？”
- **讲法**：
  - 原因：用可核对的拆解方法（例如销售额 = 客流 × 转化 × 客单，乘法用对数变成可加），加下钻和对照组比较；模型只把结果讲成话。
  - 建议：讲清产品替用户算好了什么（不做会怎样、要动多少、这个幅度历史上现不现实、先从哪看），具体动作留给用户；数据里没有可选动作时，模型给的建议只能是空话。
  - 解释方法和因果分开说：模型解释说明“模型依赖了什么”，不代表业务原因。
- **查证**：提示里的禁止项、校验规则、页面上的免责说明。

## 7. “我注意到你有 X，是怎么做到的”：逐句拆简历

- **底层在问**：简历上的每个特性是不是真的设计过，你能不能讲出机制和取舍。
- **做法**：把简历这段经历逐句拆开，每个特性出一题，例如“结论两次运行一致是怎么做到的”“接入一个新数据源要做什么”“对话怎么接住追问”。
- **讲法**：先讲机制（具体到脚本、规则、校验），再讲为什么这样设计、否决过什么，最后讲怎么确信它成立（测试、AA、回查数据）。不讲“为什么值得写进简历”。
- **查证**：对应的代码、测试和 spec。

## 8. 复杂度取舍（只在简历或回答提到时）

- **底层在问**：技术选择背后的产品判断：效果、成本、可解释性、可复现。
- **典型题**：“为什么用这个模型，不用更复杂的（深度学习、大模型）？”“为什么不微调？”
- **讲法**：从数据量、可解释性、确定性、运行成本讲；说清有没有实测对比，没测就说是判断。配一个“不确定时退回简单方法”的门槛更有说服力。用户若混淆了概念（例如把解释方法当成模型），先澄清再答。
- **查证**：决策记录和对比实验表。用户记得“做过对比”就认真找。

## 9. 降级策略

- **底层在问**：fallback 原则，不是工程操作。
- **讲法**：
  1. 一条总原则（例如“降级只降表达，不降数字的正确”）。
  2. 分层降级表：哪层出问题 / 退到哪 / 用户看到什么 / 承诺变没变。
  3. 线上几类问题（超时、限流、费用、数据过期、改动出错）分别落到哪一层，盯什么指标。
  4. 降级要看得见：结果标明来自模型还是规则。
- **常见追问“流量涨 10 倍”**：只用压测和决策记录里的真实数据讲；没设计过就直说，后面讲“先测再决定”。

## 10. 核心策略清单：为什么、怎么定、怎么回查

- **底层在问**：面试官会挑一条策略连问三件事：为什么要有、数字怎么定、怎么知道定得对。
- **讲法**：列表格（策略 / 为什么做 / 怎么定的 / 现状），再挑一条有 bad case 的深挖。门槛是经验值就承认。
- **一定要用历史数据回查门槛**：把门槛套到全部历史上，看哪些情况会被误判（例如大促后的正常低谷被当成“数据没入齐”）。回查常常能发现真问题，发现了就告诉用户、修掉，再写进卡片。
- **查证**：决策记录、spec 验收项、代码注释里的 bad case、实际数据。

## 11. 业务价值

- **底层在问**：产品能多带来多少收入或少损失多少，怎么证明是它带来的。ROI 在这里指业务收益，不是成本。
- **讲法**：
  - 把价值拆到收入公式里：产品影响哪一项，或者帮业务早发现、追回了什么。
  - 传导链表：产品做的事 → 用户行为（过程指标）→ 结果指标 → 收入 → 现在的数据〔线上 / 离线 / 估算 / 缺〕。
  - 归因用随机留出：随机留一部分用户或门店暂时不用，比较两组。不要拿“用户采纳的”和“没采纳的”比，用户本来就会挑更严重的处理，会高估效果。
  - 省时这类价值没有数据就不报数字。
- **追问**：“对照组晚发现问题，不就吃亏了吗？”

## 12. bad case

- **底层在问**：你能不能把零散的问题归纳成几类，找到每类的成因，修复后整体变好了多少。
- **讲法**（四段式）：
  1. 分类：遇到了哪几类 bad case，每类由什么原因造成。
  2. 举例：每类一个具体例子。
  3. 解决方案：每类对应的解法。
  4. 结果影响：解法迭代进去之后对整体结果的影响，数字带口径；没修完的写“待修”。
- 口头版先说“分 N 类”，每类讲完原因、例子、解法、结果再讲下一类。逐条记录表（时间 / 发现 / 怎么发现 / 原因 / 修法 / 验证）放在卡片细节里，供追问时挑。
- **常见追问**：“为什么不改提示词，而是写规则？”

## 13. 实习经历的调整

- 不用硬讲成完整闭环项目，按“我参与的三四块”组织，每块走：为什么做（需求从哪来）/ 怎么做（策略和判断）/ 结果（带口径）/ 不完美。
- 没有代码仓库时，事实来自本人口述和已投简历；口述逐条问清楚，和简历口径冲突的地方先指出来。
- 内部信息只用于准备，不进对外材料。
